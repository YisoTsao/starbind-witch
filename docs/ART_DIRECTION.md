**規則：** B、C 只決定「有哪些東西、長什麼樣子」；**亮度、色彩、像素密度、比例一律以 A 為準**。

### 1.1 實測結論（影響全部美術規範）

| 量測項目 | 圖 A | 圖 B | 圖 C |
|---|---|---|---|
| 解析度 | 1672×941 | 1536×1024（JPG） | 1536×1024 |
| 一個「美術像素」約等於 | **≈3.15 螢幕像素**（非整數） | 不一致，無穩定格線 | 不一致，無穩定格線 |
| 換算原生美術解析度 | **≈530×299** | — | — |
| 標稱 Tile 實際大小 | 推得 32 px tile ≈ 100 螢幕 px | 標示「32×32」，實際約 **47 px** 且有間隙 | 地板塊約 **57 px** |
| 平均亮度 (0–1) | **0.57**（白天） | 0.31（紫色黃昏） | 0.24（夜晚室內） |
| 不重複色數 | ≈61 萬 | ≈25 萬 | ≈37 萬 |

推論：

1. 三張都是 AI 生成的「像素風插畫」，**不是索引色的真正像素圖**（正式像素素材通常每張 < 64 色）。邊緣有抗鋸齒、模糊與非整數縮放。
2. 圖 A 原生約 530×299 美術像素，**與目標虛擬解析度 480×270 幾乎一致**；魔女在圖 A 約高 33 美術像素 ≈ 1 tile。也就是說 **32×32 tile + 480×270 這組規格與圖 A 相容**，不需要改 tile 尺寸。
3. B、C 的色調被「黃昏/夜晚光照」烘焙進去，若直接使用會與 A 的白天場景衝突。夜晚效果應由 URP 2D Light / 後處理產生，素材本身維持中性白天色。

## 2. 技術像素規格（定案候選）

| 項目 | 規格 | 備註 |
|---|---|---|
| Tile 尺寸 | **32×32 px** | 與圖 A 相容，維持 GDD 原規格 |
| Pixels Per Unit | **32**（全專案統一） | 1 tile = 1 Unity unit |
| 參考解析度 | **480×270** | 1080p = 4×、4K = 8× 整數倍 |
| 可見範圍 | 15 × 8.4 tiles | 圖 A 約 16.6 × 9.3 tiles，接近 |
| Filter / 壓縮 | Point (no filter)、Compression None、Mip Map 關閉 | |
| 像素格對齊 | 所有素材 1 美術像素 = 1 貼圖像素；禁止混合縮放（no mixels） | 角色、地磚、VFX 同密度 |
| 旋轉 | 遊戲物件避免任意角度旋轉像素圖；投射物使用 8/16 方向預繪 | 旋轉會破壞像素格 |

> 1440p（5.33×）與 Steam Deck 1280×800（2.67×）不是整數倍，見 `SPEC_CONFLICTS.md` C-04。

## 4. 視角與造型

- 正交俯視 **3/4 RPG 視角**：地面看頂面，建築、樹幹、懸崖同時看到**正立面**；**不是 45° 等角**。
- 所有物件的「接地線」水平，正立面垂直，不做菱形格。
- 光源統一：**左上方**主光，陰影落向右下；陰影使用半透明深色像素（非模糊）。
- 物件底部有 2–4 px 接地陰影（獨立 Sprite 或烘在物件底部，同一類物件統一）。

## 5. 色彩

### 5.1 主調色盤（取自圖 A 的 8 色主群，作為起點）

| 角色 | 色碼 | 用途 |
|---|---|---|
| 草地中間色 | `#8AB658` | 草地主體 |
| 草地亮部 | `#AEC361` / `#C7D77A` | 草尖、受光面 |
| 草地暗部 / 樹葉陰影 | `#4D8776` | 冷色陰影（偏藍綠，非純黑） |
| 土路 | `#D9B87F` | 道路主體 |
| 紫瓦 / 品牌紫 | `#8D4C82` | 屋頂、旗幟、魔女帽 |
| 花樹粉 | `#B98083` 系 | 花樹、花叢 |
| 輪廓 / 最深 | `#343556` | 深色描邊（深紫藍，非純黑） |

- 正式調色盤：上列擴充為 **48–64 色主盤**（含水、岩、木、皮膚、魔法色），存放於 `art-source/palette/starbind_main.gpl`（待建立），所有素材索引到此盤。
- **陰影色相偏移**：陰影往藍紫，亮部往黃綠／暖色；避免只調亮度。
- 輪廓：外輪廓使用比填色深 2–3 階的同色相顏色；角色外輪廓可用 `#343556` 系，以在草地上保持可讀。

## 6. 各類素材標準

### 6.1 角色
- 4 方向（下/上/左/右，左右可鏡像但需檢查不對稱細節如帽飾）；八方向移動以四方向動畫表現。
- 最低動畫：Idle 4 幀、Walk 6 幀、Cast 4–6 幀、Melee ×3 段、Dash 3 幀、Hit 2 幀、Death 6–8 幀。
- 以 12 FPS 為基準節奏，關鍵影格可延長。
- 魔女辨識特徵：紫色寬簷帽＋白花飾、粉色長髮、紫裙（取自圖 A）。

### 6.2 地形（Tilemap）
- 一律 32×32、可無縫重複。草地至少 4 個變體＋花點變體。
- 轉角使用 **47 格 Blob（Rule Tile）** 或 **16 格 Wang** 規格，需附規則表（見 `ASSET_PIPELINE.md` §5）。圖 B 的 Autotile 區只有「四角環繞一個洞」的示意，**不是可用的 Autotile 組**。
- 地形紋理不得有明顯方塊格感；細節分布打散。

### 6.3 建築
- 小屋外觀拆成：屋頂（Foreground，可淡出）、牆面與門窗（World，接地 Pivot）、煙囪/燈/花藤（裝飾子物件）。
- 門洞為獨立互動區。

### 6.4 植被
- 樹 = 樹幹（World，有 Collider）＋樹冠（Foreground，玩家在下方時半透明）。
- 小花草為 GroundDetails，無碰撞。

### 6.5 UI
- 品牌色：暗紫＋金（GDD §12.3），但遊戲內 HUD 簡潔，不使用圖 B/C 那種大面積發光框線。
- 像素字型：中文需要 12 px 或 16 px 點陣字（繁中字數多，授權需確認，見 `ASSET_GAPS.md`）。
- UI 以參考解析度的整數倍渲染。

### 6.6 魔法特效
- 透明 Sprite Sheet，像素輪廓清楚；分級 S/A/B（GDD §12.1）。
- 每個特效具 start / loop / end。
- Bloom 只作用於指定高亮像素（URP 2D + 選擇性發光材質），不能糊掉全畫面。
- 學派主色：火 橘紅、冰 青白、雷 黃紫、自然 黃綠、月影 深紫、星痕 金白（待確認）。

## 7. 禁止事項

- 不把整張參考圖當背景貼圖。
- 不把有文字、框線、標題、深色展示底、發光光暈底的圖區直接匯入為 Sprite。
- 不使用非整數縮放的像素素材；不使用 Bilinear Filter。
- 不在素材中烘焙夜晚/黃昏整體色調。
- 不使用未標示的隨機色方塊冒充正式素材。除錯用碰撞標記 Tile 只在編輯器可見（見 `TECH_ARCHITECTURE.md` §6）。

## 8. 紫幻森林 Moonveil（2026-11-26 新增，World & Visual Overhaul）

使用者提供四張紫幻森林參考圖（`references/01`–`04`），作為**森林類 Biome 的視覺目標與地圖設計基準**。村莊與工坊仍以圖 A 為準；兩者共用 §2 的技術像素規格（32×32、PPU 32、480×270、Point）。

| 參考 | 作用 | 實測 |
|---|---|---|
| 01 Overview | 區域拓樸與地標配置（`LEVEL_DESIGN.md`） | 1448×1086；座標換算 9.05 px/tile |
| 02 Gameplay | 鏡頭、比例、密度、HUD；**本 Biome 的主要畫面目標** | 1672×941；1 美術像素 ≈3.48 螢幕像素 → 原生約 480×270；魔女 ≈34 px，與現有規格一致 |
| 03 Tileset | 地形種類與調色來源 | 每格約 92–95 px（非整數、非真像素），不是可用的自動拼接組 |
| 04 Props | 物件目錄 | 透明底，alpha>200 可乾淨切出；同一張內比例不一致（樹與花叢比例比圖 02 大） |

### 8.1 Moonveil 色彩與層級

- 主色：紫樹冠（亮 `#c27be0` 系、暗 `#5b3a8a` 系）、暗藍綠林地、亮橄欖草地、土路暖粉褐、星光深藍水、紫灰岩。實際色盤由 `tools/art/moonveil_art.py` 從圖 03/04 取樣。
- 夜色仍由 Global Light 產生（本 Biome：色 (0.94, 0.90, 1.0)、強度 1.0），素材本身中性。
- 亮度層級沿用 §5.2：草地最低對比；樹冠中；角色、敵人中高；敵方預警最高。第一版（強度 0.8＋偏紫）讓整體偏暗，已提高。

### 8.2 REF-DRAFT 規則（本次新增的素材狀態）

- 物件依類別縮放（樹 0.50、遺跡/營地 0.38–0.44、中型 0.34、小型 0.24–0.28），使比例對齊圖 02；全部量化到同一 64 色盤，外緣 1 px 加深。
- 這是**可替換的草稿**，與 §7「不把 AI 概念圖匯入為正式 Sprite」不衝突的前提：名稱帶 `_mv_` 並在 `ASSET_CATALOG.md` 標示 REF-DRAFT、列入 `MISSING_ASSETS.md`，正式版重繪。先例：`extract_characters.py`。
- 「是否已達參考圖品質」：**未達到**。比較用實機截圖見 `docs/evidence/moonveil/`，差距見 `MISSING_ASSETS.md` §0。
