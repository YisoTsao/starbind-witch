## 0. 最終決策與設計禁區

### 0.1 最終產品定位

一款**單人操作一位魔女**的精緻像素、俯視 2D Action Roguelite。玩家在連續可探索地圖自由行走、閃避、近距離使用法杖、主動施法，並以隨機獲得的書頁配置自動魔法。以「**改寫咒語規則**」作為差異化賣點，利用元素反應、法術形態和修飾模組組出自己的清怪流派。

**一句話玩法：** 用魔杖在森林中邊跑邊打，撿取失控書頁，把普通小法術改造成巨大連鎖魔法，擊退怪潮並探索魔典異常的起源。

### 0.2 已確定事項

| 類別 | 決議 |

### 0.3 暫不做（硬性範圍控制）

- 四名可切換主角、多人連線、AI 戰鬥隊友。
- 無限制程序生成開放世界、無限地圖、完全可破壞像素物理。
- 六元素之間所有組合、幾百張獨立手繪法術動畫。
- 複雜裝備詞綴洗鍊、拍賣、線上商城、即時雲端存檔。
- 在核心戰鬥沒通過測試前，批量製作完整世界的地圖與怪物。

### 0.4 品質與驗收原則

1. **能玩優於展示：** 任何場景必須能在 Unity Game View 實際移動，才稱為可玩場景。
2. **美術與邏輯分離：** 特效只是顯示，不決定實際命中和傷害。
3. **逐級驗收：** 每階段都須附操作方式、場景路徑、測試證據與已知限制。
4. **配置可重現：** 隨機地圖、掉落與升級使用 seed，便於修 bug。
5. **先證明核心好玩：** 玩家願意連續玩 3～5 分鐘戰鬥且主動技能有意義，再擴大規模。

## 1. 遊戲摘要與產品目標

- 類型：2D Pixel Art Action RPG / Roguelite / Spellcraft / Horde Combat。
- 目標裝置：PC Windows，鍵盤滑鼠優先；手把為延伸項目。
- 一局正式目標：15～25 分鐘；**Demo：10～12 分鐘**。
- MVP 目標體驗：從小屋出生 → 接任務 → 進入森林 → 連續移動與清怪 → 升級構築 → 怪潮 → Boss → 帶著研究資源回村莊。
- 獨特主張：三頁魔典（形態、元素、修飾）+ 高風險「失控書頁」+ 共鳴超載，將主動與自動魔法整合。
- 定價、銷量、開發月數均非本文件的保證項目；以上架前的試玩與市場驗證再定案。

### 1.1 設計支柱

1. **走動探索是真正玩法：** 岔路、橋梁、懸崖、水道、NPC、寶箱、事件、敵人分布具功能。
2. **操作與割草兼具：** 自動魔法清雜兵，主動技能精準聚怪、破盾、反應與應對精英。
3. **有限規則產生多種組合：** 不靠大量固定技能，而靠模組交互產生 Builds。
4. **反應清楚、不濫炸：** 畫面可以華麗，但攻擊警示、地形、角色永遠先被看清楚。
5. **成本可控的可重用美術：** Tilemap、可重用 Props、Sprite Sheet、程序化粒子混合。

「艾斯特拉」的魔法由星痕、月影與自然元素維持平衡。星露村的魔女露米在工坊研究一冊古老禁書《失控魔典》，卻意外喚醒書內能自行改寫法術的力量。月影森林首先出現異常：蘑菇產生毒性、古樹甦醒、星核礦脈暴走。露米一方面尋找魔典書頁，一方面修復魔法秩序。

- **艾拉：** 老魔法研究者，提供魔典教學、研究解鎖與主線任務。
- **凱恩（騎士）：** 訓練場、近戰操作指導、守衛任務。
- **莉亞（祭司）：** 回復、淨化、遺物解說。
- **洛恩（弓箭手）：** 森林路線、隱藏區域、狩獵委託。

### 2.4 第一段主線任務

1. **起床與異動：** 玩家在魔女小屋外出生；艾拉發現魔典頁面發亮。
2. **法杖試練：** 在訓練場操作移動、三段法杖、蓄力魔彈、閃避。
3. **初次書頁：** 在工坊配置火焰飛彈、取得第一個自動魔彈。
4. **前往森林：** 出村沿路到月影森林，遇到基本怪。
5. **首次反應：** 取得風元素或冰元素書頁，教學連鎖攻擊。
6. **清除異常：** 怪潮、精英與月蝕菇王。
7. **返回研究：** 撿取魔典殘頁，回村解鎖研究節點，開啟下一局。

## 3. 實際遊戲地圖 / 攝影機 / 美術

### 3.1 風格基準

以使用者最後提供的 **Unity Top-down Tilemap 參考截圖**作為鏡頭與可玩地圖標準：畫面可顯示屋頂和建築正面，玩家在草地／道路上自由走動；不是以前一張畫面塞滿 UI、燈光與花朵的宣傳插畫。

| 規格 | 初版建議 |
|---|---|
| 格線 | 32×32 px / Tile |
| 主要攝影機 | Orthographic、跟隨玩家、限制邊界 |
| 參考虛擬解析度 | 480×270；4 倍至 1920×1080 |
| Sprite Filter | Point，無有損壓縮 |
| 角色顯示 | 高度約 48～64 px，Canvas 視動作 96×96 |
| 地形 | 重複 Tile + Autotile / Rule Tile |
| 大型物件 | 透明獨立 PNG：樹冠、房屋、書櫃等，可跨越多格 |
| 碰撞 | Tilemap Collider 2D + Composite Collider 2D；大型物件獨立 Collider |
| 排序 | Ground < Decal < Props < Characters < Canopy；必要時 Y 軸排序 |
| 光影 | 局部 URP 2D Light，場景低對比、技能高對比 |

### 3.2 Tilemap 圖層

```
WorldRoot
├── GroundBase        # 基礎草地、石面
├── GroundTransition  # 路沿、混色、草地轉角
├── Water             # 水面與水域動畫
├── Path              # 土路、石磚
├── Cliff             # 岩壁、崖邊、階梯
├── GroundDetails     # 小草、落葉、泥痕
├── BlockingProps     # 樹幹、石柱、柵欄、建築
├── Characters        # 玩家、NPC、敵人
├── Foreground        # 樹冠、房簷、遮擋
├── Effects           # VFX 及地面範圍提示
└── UI
```

### 3.3 區域關卡規則

- 出生村莊：人工規劃，不隨機生成，安全區禁止敵人生成。
- 月影森林：以**手工路線骨架**為主，可重排怪物群、資源點和事件；不做無限 procedural map。
- Demo 森林灰盒：**64×64 格**起步；可延展到 128×128，按效能與可玩性決定。
- 每個交戰區至少保留可閃避／繞行的空間；大型裝飾不得封死主路。
- 怪物不得生成在河水、懸崖、實體建築或畫面直接可見的玩家安全圈內。
- 地圖資料具 `seed`，同一 seed + 同一版本輸出一致的敵人與事件位置。

### 3.4 出生地功能布局

- 魔女小屋：門口互動（E）進入室內；桌、床、書櫃、煉金台、研究桌。
- 中央小廣場：玩家出生位置、傳送星盤、路牌。
- 騎士訓練場：靶子、木偶、法杖連擊教學。
- 溪水與小橋：提供可辨識地形邊界及進出路線。
- 森林出口：從村莊連接到探索關卡，可使用邊界切換但不是戰鬥房間過場。
- 祭司與弓箭手：簡單 NPC 站位及少量對話；不急著做完整分支任務。

### 3.5 美術資產製作原則

1. PNG RGBA；除基礎覆蓋地磚外，獨立物件須透明背景。
2. 所有地磚嚴格以 32×32 對齊；Autotile 採 Unity Rule Tile 配置，需附規則表。
3. 樹木、房屋、桌椅不限 32×32，但**世界比例**需固定；Pivot 以腳底／物件接地點為準。
4. 不能將帶字體、標題、示意格線、烘焙陰影的 AI 展示圖當正式 Tileset。
5. 為每一資產提供唯一 ID、像素尺寸、透明度檢查、碰撞設定、渲染圖層。
6. AI 圖可作風格參考；正式地磚需經無縫檢測，不能靠自然語言 Prompt 保證完全對齊。
7. 角色、地磚、VFX 的像素密度一致；Bloom 只能在局部強化，不能糊掉像素邊緣。

### 4.3 法杖物理攻擊

- 三段連擊：平掃（10）→ 回身敲擊（12）→ 魔力震擊（18）。
- 第三段提供輕度破韌／擊退，但**Boss 不會被普通連擊無限打斷**。
- 命中回復 MP：每一次不同攻擊事件對單一敵人的第一次命中回 2 MP；限制每秒上限，防止群怪無限回魔。
- 完美閃避：敵人攻擊的危險窗內閃避成功，下次魔彈得到一次小型附加傷害；不強迫玩家近戰。
- 若短按／長按同鍵手感不佳，允許切換方案：左鍵近戰、右鍵蓄力；按鍵應可重綁。

### 4.4 戰鬥視覺回饋

- 受擊：0.08～0.12 秒閃光、短擊退、音效、少量螢幕震動。
- 命中：白色短閃，元素狀態以小圖示或低強度顏色呈現。
- 精英攻擊：地面紅色/暖色明確預警，視覺優先權高於我方技能。
- 死亡：操作鎖定、結果頁、回工坊，不原地硬重置所有系統。

## 5. 魔法系統 v3：形態 × 元素 × 修飾

### 5.1 三頁魔典

每一個玩家裝配的可構築法術 = **形態 (Form)** + **元素 (Element)** + **修飾 (Modifier)**，另有基礎數值、觸發方式與代價。

- **形態**決定碰撞方式：飛彈、領域、環繞、光束（光束第二階段）。
- **元素**決定狀態：火、冰、雷、自然、月影、星痕（Demo 先火/冰/雷，後續擴展）。
- **修飾**決定行為：分裂、穿透、追蹤、迴響（MVP 優先分裂/穿透）。
- **觸發模式**獨立於法術資料：主動（使用者按鍵）或自動（條件/週期觸發）。

### 5.2 六個學派長期定位

| 學派 | 狀態 / 特性 | 代表法術 | 開發階段 |
|---|---|---|---|
| 火焰 | Burning / DoT / 爆炸 | 火球、烈焰漩渦、隕石 | Demo |
| 冰霜 | Chill / Freeze / 碎裂 | 冰箭、冰環、冰晶爆破 | Demo |
| 雷霆 | Shock / 跳躍電弧 | 雷擊、連鎖電弧、電場 | Demo |
| 自然 | 毒、藤蔓、召喚 | 毒花、荊棘、藤蔓守衛 | 之後 |
| 月影 | 詛咒、牽引、幻影 | 暗影之手、虛空裂縫 | 之後 |
| 星痕 | 複製、反彈、改寫規則 | 星彈、星界迴響 | 之後（星彈可簡化示範） |

### 5.3 MVP 可組合內容（必須受控）

**MVP 實作：** 3 元素（火/冰/雷）、3 形態（飛彈/領域/環繞）、2 修飾（分裂/穿透），但**不是全部 3×3×2 都直接上線**。先交付 6 個白名單組合，逐步開放。

| Spell ID | 預設名稱 | 形態 | 元素 | 修飾 | 觸發 |
|---|---|---|---|---|---|
| `fire_bolt` | 火球術 | 飛彈 | 火 | 無 | 主動 |
| `frost_orbit` | 冰晶環繞 | 環繞 | 冰 | 無 | 自動 |
| `chain_spark` | 雷弧落擊 | 領域/目標點 | 雷 | 無 | 主動 |
| `split_flame` | 分裂火球 | 飛彈 | 火 | 分裂 | 主動 |
| `piercing_ice` | 穿透冰晶 | 飛彈 | 冰 | 穿透 | 主動 |
| `thunder_pulse` | 自動雷脈衝 | 領域/目標點 | 雷 | 無 | 自動 |

> 旋風牽引是 **特殊控制法術**，不必硬塞進六元素表。第一版以獨立 `wind_pull` 技能形成火焰龍捲的招牌連攜。

### 5.4 初始技能數值（平衡起點）

| 技能 | 傷害 | CD | MP | 其他 |
|---|---:|---:|---:|---|
| 火球術 | 18 | 0.65 秒 | 5 | 命中附加 Burning 4 秒 |
| 冰箭 | 12 | 0.8 秒 | 6 | Chill 30%，持續 2.5 秒 |
| 雷擊 | 22 | 2.8 秒 | 14 | 目標點範圍 1.5 單位 |

| 冰晶環繞 | 8/次 | 自動持續 | 0 | 命中各敵有內部 CD |
| 追蹤魔彈 | 9 | 自動每 2.5 秒 | 0 | 攻擊附近最近敵人 |

**同一技能傷害與狀態不等於連鎖反應額外傷害。** 數值需透過實際 DPS、清怪速度、死亡原因調整。

### 5.5 元素狀態與主反應規則

- 敵人最多兩個主要元素狀態；後加入狀態更新/替換較舊者。
- 新攻擊命中時先結算直接傷害，再檢查 `ReactionResolver`。
- 同一 Hit Event **最多觸發一種主反應**；反應消耗使用的元素標記。
- 反應的次生傷害標記 `CannotTriggerReaction=true`。
- 同一受擊者同一反應有 0.5 秒內部保護期，避免多段 VFX 無限觸發。
- 群體連鎖限制每一反應最多命中 8 個有效目標；超載可增加，但仍有上限。

| 組合 | 反應 | 效果（設計） |
|---|---|---|
| 火＋冰 | 蒸汽爆裂 | 半徑 1.8 AoE 追加傷害，短暫煙霧（視覺不遮警示） |
| 火＋雷 | 超載爆燃 | 主目標周圍額外範圍爆炸 |
| 冰＋雷 | 碎晶雷暴 | 擊碎冰凍效果，電弧跳躍附近最多 3～5 名敵人 |
| 火＋旋風 | 火焰龍捲 | 旋風吸收燃燒狀態並變成 3 秒移動火焰區域 |

其他六學派反應保留在未來擴充表，不在 MVP 堆出 15 種關係。

### 5.6 失控書頁（風險與代價）

- **貪婪書頁**：傷害 +30%，施放主動技能時額外付 1 HP（不可把 HP 降到 0，或另標示風險版本）。
- **倒轉書頁**：飛彈到達盡頭後折返，返程傷害 60%，但飛行速度 -15%。
- **複寫書頁**：每第三次有效施法複製低威力版本，冷卻較長且不能觸發再次複寫。
- **脆弱書頁**：暴擊率上升，最大護盾降低。

Demo 先選一張測試，避免同時引入複雜詞綴互動。

## 6. 主動 + 自動混合系統

### 6.1 技能槽配置（定案）

- 基本攻擊：法杖近戰 / 蓄力魔彈，不占法術槽。
- **2 個主動槽：Q / E**（前期有一個，教學後解鎖第二個）。
- **最多 4 個自動槽**（初始 1 槽，隨局內解鎖；Demo 只需 2 個能同時裝配）。
- **1 個超載槽：R**，與法術槽分開。
- 技能組合可在工坊裝配；局內拾取書頁後用升級畫面修飾。

### 6.2 Auto Cast 的觸發條件

```text
IF run_active AND not_paused AND player_alive
  AND slot_unlocked
  AND cooldown_ready
  AND valid_target_in_range
  AND per_frame_spawn_budget_available
THEN cast ability using the shared AbilityRunner
```

- 自動模組不消耗基礎 MP，改由專屬 CD、觸發條件及升級控制。
- 有目標搜尋上限與查詢頻率（例如每 0.15～0.25 秒更新目標）。
- 使用同一套 `HitResolver` / `DamageResolver` / `StatusEffect` 管線。
- 沒有可用目標時，不播放空擊與無用粒子。
- 不允許自動技能無限觸發自動技能（event depth + proc budget）。

### 6.3 主動施法要永遠有價值

自動技能偏向持續清雜兵；主動技能用於聚怪、打斷、破防、觸發指定反應、處理精英與 Boss。測試時若玩家只靠自動技能就能完全無腦站樁過關，則應提高敵人機制和主動技能決策價值，而不只是硬削弱所有自動技能。

## 7. 魔典超載 Arcane Overdrive

### 7.1 取得共鳴（初始值）

| 事件 | 共鳴 |
|---|---:|
| 法杖完整第三段命中 | +2 |
| 主動法術直接命中 | +1；每次施法有上限 |
| 觸發主元素反應 | +8 |
| 精英或 Boss 重要攻擊完美閃避 | +5 |
| 擊殺敵人 | +1；每秒總上限 |

- 最高 100；不應透過空放技能充能。
- 使用 R 需 100；啟動後清零。
- 持續 8 秒；主動技能冷卻 -25%、反應傷害 +35%（初始平衡值）。
- 同時只維持一種 Overdrive；時間到平順退出，不能永久堆疊。
- 各流派在超載期間可附加視覺與變招，但 **不應讓 VFX 每秒倍增到不可控**。

### 7.2 失控超載（正式版候選）

共鳴未滿時以 HP 為代價提前啟動，暫不進 Demo。若實裝，需清楚標示代價、最低生命門檻、冷卻與使用時機，避免意外自殺和操作誤觸。

## 8. Roguelite 升級與 Build

### 8.1 單局升級機制

- 怪物掉落星屑 XP；經驗自動吸附，避免玩家花大量時間撿取。
- 升級時彈出**三選一**；選擇期間暫停戰鬥或慢動作，Demo 採暫停。
- 升級卡類型：主動法術改造、自動法術、元素強化、通用被動、稀有失控書頁。
- 稀有卡必須有條件或 Build 關聯，避免早期拿到完全不能用的修飾。
- 卡池採權重與解鎖條件，並保留 seed 可重現。

### 8.3 推薦的五種流派

1. **星雨爆發流**：分裂、穿透、星火護符，利用連續飛彈與爆破清群。
2. **元素反應流**：火球＋冰晶＋雷擊，利用主動施法串接反應。
3. **環繞割草流**：冰晶環繞＋魔彈增殖＋移速，透過走位保持傷害。
4. **控場旋風流**：旋風牽引＋火焰＋反應增幅，集中敵人爆發。
5. **魔武近戰流**（正式版候選）：法杖連擊、完美閃避、近戰回魔與短距離法術爆發。

### 8.4 永久成長

- `GrimoireResearch`：擴充能出現的書頁/形態/元素組合；優先提供**選項**而非永遠數值碾壓。
- `StaffWorkshop`：解鎖不同法杖攻擊模式。
- `AlchemyStation`：開放藥劑配方。
- `StarTalent`：有限的 HP、移速/MP 等基礎強化。
- 局內死亡：不保留當局等級與卡片，保留指定的研究材料與永久解鎖。
- 首版存檔採本機 JSON、版本號與簡單校驗；不可直接序列化 Unity Object 引用。

## 9. 裝備、背包、素材與掉落

### 9.1 物品分類

| 分類 | 用途 | 局內/局外 |
|---|---|---|
| 武器（法杖） | 改變近戰、蓄力與特殊屬性 | 出發前裝配 |
| 帽子 / 披風 / 護符 | 輕量屬性與被動 | 出發前裝配 |
| 消耗品 | HP、MP、短暫護盾 | 局內 |
| 魔法書頁 | 法術組合、局內選卡 | 依規則 |
| 製作素材 | 星砂、月露、魔晶、孢子 | 結算後部分保留 |
| 遺物 | 特殊 Build 規則 | 局內及後續收藏 |
| 劇情道具 | 任務事件 | 永久任務進度 |

### 9.2 裝備欄位（第一版）

- 1 主法杖、1 護符；帽子／披風先只作外觀設定或正式版延伸，避免 UI 過量。
- 三把設計法杖：`sprout_staff`（近戰回魔）、`moonring_staff`（蓄力彈折返）、`storm_staff`（每第三次有效施法追加小電弧）。
- 兩個護符：`ember_charm`（燃燒時間小幅延長）、`frost_brooch`（冰凍敵人的首次受擊傷害增加）。
- 裝備屬性修改透過 StatModifier，不讓各裝備直接修改角色核心邏輯。

### 9.3 消耗品與材料

- 生命藥水：回復 30 HP；初始攜帶 2，使用快捷鍵 `1`。
- 魔力藥劑：回復 35 MP；使用快捷鍵 `2`。
- 星砂：常見永久研究材料；月露：森林探索資源；孢子：蘑菇敵人掉落；星核碎片：精英/Boss 材料。
- 掉落表由 `LootTableDefinition` 設計；普通怪不可掉落大量遮擋畫面的物件，採適度自動收集。

### 9.4 背包與物品設計規則

- MVP 背包採**清單/格子管理**，不做物品重量與複雜 Tetris 擺放。
- 同類材料可堆疊；裝備與唯一遺物不可堆疊。
- `ItemId` 為唯一鍵，不依 Sprite 名稱判斷類型。
- 拾取、使用、掉落、存檔都有明確事件；不可因 UI 重新整理而重複給物品。

### 10.2 怪潮成長（10～12 分鐘 Demo）

| 階段 | 目標同屏活敵 | 事件 |
|---|---:|---|
| 0–2 分 | 5–12 | 基礎移動、火球、追蹤魔彈 |

- 停止重複大量 Instantiate / Destroy；攻擊碰撞優先 Physics2D NonAlloc / 空間查詢與時間分散。
- 怪物死亡動畫、受擊特效要限量；同批次傷害數字可合併。

## 12. Pixel VFX / Audio / UI

### 12.1 VFX 分級

- S：超載、大型火焰龍捲、Boss 爆發。畫面同時 1～2 個明顯主焦點。
- A：火球爆炸、冰爆、雷鏈。適量使用，視敵群合併重複表現。
- B：命中火花、燃燒、微粒、傷害數字。大量但低成本。

### 12.2 推薦 VFX 管線

1. 正式特效優先使用具有清楚像素輪廓的透明 Sprite Sheet。
2. Unity Particle System 控制位置、速度、火星及命中補強；Shader Graph 用於局部顏色與光暈。
3. 大型 3D 旋轉特效可選 Blender 正交渲染成 2D，再像素化與人工修格；**不是必備工作流**。
4. 每個 VFX Prefab 具 `start/loop/end`、持續時間、繪圖排序、對象池重用。
5. 特效不控制傷害判定，敵人群聚時不為每隻怪完整生成一套高成本火焰龍捲。

### 12.3 必要 HUD

- 左上：角色 HP、MP、共鳴；狀態效果小圖示。
- 右上：簡化小地圖、當前區域/任務。
- 下方：Q/E 主動技能、R 超載、1/2 消耗品，冷卻清楚。
- 怪物：精英/Boss HP；普通怪僅必要時顯示簡化血條。
- 暫停：背包/魔典分頁；關卡成長三選一卡片介面。
- UI 色彩：暗紫/金色為品牌，遊戲內 HUD 應**簡潔**，不可佔滿整個畫面。

### 12.4 音效

- 基礎：腳步、法杖三連、火球、冰爆、雷鏈、擊中、收集、升級、超載啟動/結束、Boss 預警、UI 點擊。
- 音效分組：Master、Music、SFX、UI，設定可調音量及簡易靜音。
- 超載音樂可增加層次，但須可辨識怪物攻擊警示。

### 13.2 模組邊界

| 模組 | 職責 | 禁止 |
|---|---|---|
| `PlayerController` | 方向移動、Dash、碰撞 | 不計算法術傷害 |
| `CombatInput` | 輸入映射、短按/長按解析 | 不直接生成特效 |
| `AbilityRunner` | 施法條件、冷卻、消耗與實例 | 不決定敵人 AI |
| `AutoCastController` | CD、搜索目標、觸發規則 | 不自行寫另一套傷害 |
| `SpellFactory` | 將頁面配置組合成執行法術 | 不直接編輯 SO 原檔 |
| `HitResolver` | 命中、穿透、傷害事件 | 不顯示 UI |
| `StatusController` | 元素狀態與到期 | 不實例化大量粒子 |
| `ReactionResolver` | 元素反應與觸發預算 | 不遞迴觸發自身 |
| `EnemyAI` | 追擊、攻擊、避障、狀態切換 | 不管理全局怪潮 |
| `SpawnDirector` | 波次、區域、上限、難度 | 不直接綁特定 Enemy Prefab |
| `UpgradeDirector` | 三選一、權重、前置 | 不修改永久存檔 |
| `ItemInventory` | 添加/移除/堆疊/使用 | 不讓 UI 自行改數量 |
| `RunManager` | 開始、結束、局內狀態 | 不承擔全部系統 |
| `SaveService` | 持久化、版本遷移 | 不存 Unity 物件指標 |
| `VFXManager` | 播放、物件池、品質分級 | 不決定真實傷害 |

### 13.3 ScriptableObject 定義

- `CharacterDefinition`：基礎屬性、Prefab、動畫控制器。
- `SpellDefinition`：法術 ID、基礎數值、施法條件、形態。
- `SpellFormDefinition`：飛彈/領域/環繞等實作參數。
- `ElementDefinition`：狀態、相容反應標記。
- `ModifierDefinition`：分裂、穿透、迴響等規則。
- `ReactionDefinition`：元素配對、反應數值、上限。
- `UpgradeDefinition`：稀有度、權重、前置、可重複次數。
- `ItemDefinition`：類型、堆疊、圖標、使用方式。
- `EquipmentDefinition`：裝備欄、StatModifier、被動效果。
- `EnemyDefinition`：HP、AI 策略、攻擊、掉落。
- `MapBiomeDefinition`：地形、物件池、敵人權重、規則。

### 13.4 主要資料流

```text
Input / Auto Trigger
    -> AbilityRunner
    -> SpellInstance + CastContext
    -> Projectile / Area / Orbit
    -> HitResolver
    -> DamageResolver
    -> StatusController
    -> ReactionResolver (bounded)
    -> CombatEventBus
    -> VFX / Audio / UI

RunManager -> UpgradeDirector -> RuntimeBuild -> SpellFactory
RunManager -> RunResult -> SaveService -> PermanentProgression
```

### 13.5 重要資料欄位

```csharp
public struct CastContext {
    public int CastId;
    public string SourceSpellId;
    public Vector2 Origin;
    public Vector2 Direction;
    public float DamageMultiplier;
    public bool CannotTriggerReaction;
    public int ProcDepth;
}

public struct DamageEvent {
    public int CastId;
    public int SourceEntityId;
    public int TargetEntityId;
    public float Amount;
    public ElementType Element;
    public bool CannotTriggerReaction;
}
```

要求：同一 Hit 在一次施放上下文中去重；反應深度與獨立事件上限均可配置。若目前 Unity/C# 版本有不同 API，可在實作時修正，但不能改變行為契約。

### 13.6 事件設計

`OnSpellCast`、`OnHit`、`OnDamageApplied`、`OnElementApplied`、`OnReactionTriggered`、`OnEnemyKilled`、`OnXpGained`、`OnLevelUp`、`OnUpgradeChosen`、`OnOverdriveStarted/Ended`、`OnItemPickedUp`、`OnRunEnded`。

訂閱必須在物件停用時解除；避免依靠全局靜態事件而發生重複觸發與記憶體洩漏。

### 13.7 性能策略

- 目標 Windows 1080p、60 FPS；**需在實際指定硬體驗證**。
- 怪物與 VFX 物件池、生成限額、反應事件上限、Damage Popup 合併。
- 自動施法目標查找分幀/降頻；敵人大群避免每隻每幀 Pathfinding。
- Unity 2D Sorting 與 Particle Systems 控制 Overdraw；URP 2D Light 數量受限。
- Profiler 紀錄 CPU、GC Alloc、渲染時間、Draw Calls、記憶體；不可只說「看起來不卡」。

## 14. 儲存、可重現性與測試

### 14.1 存檔 schema（概念）

```json
{
  "saveVersion": 1,
  "playerProgress": {
    "unlockedSpells": ["fire_bolt"],
    "unlockedItems": ["sprout_staff"],
    "researchPoints": 0,
    "completedQuests": []
  },
  "settings": {
    "musicVolume": 0.8,
    "sfxVolume": 0.9
  }
}
```

- `RunState` 另存可選，但 MVP 可只在回工坊時儲存永久資料。
- JSON 寫入採暫存檔替換，避免中途寫入損毀。
- 重要規則（XP、掉落、升級卡池）可帶 seed 進測試。

### 14.2 自動測試（EditMode）

- 法杖完整連擊結算次數正確。
- 同事件重複 Hit 只結算一次。
- `ReactionResolver` 次生傷害不再產生反應。
- 裝備 StatModifier 疊加與卸除後可恢復。
- 自動技能沒目標時不耗觸發預算。
- 升級選項符合前置與稀有度要求。
- 物品堆疊上下限、不會負值或重複領取。
- 相同 seed 可得到相同事件/掉落順序（不混入未受控隨機）。

### 14.3 玩法測試（PlayMode + 人工）

- 出生→小屋→訓練場→森林→Boss→回村完整通關。
- 30、50、60 同屏怪物時效能與畫面辨識測試。
- 每一種技能能從角色任意朝向正確施放。
- 所有障礙物可碰撞；無法卡入樹幹、房屋或懸崖。
- 精英/Boss 攻擊警示不被技能特效遮蔽。
- 失去焦點/暫停/開背包後，技能冷卻與計時器一致。

- 冰/雷、旋風、元素狀態、三反應、兩個自動模組。

- 驗收：反應可重現、沒有無限連鎖；能靠主動技巧顯著提升清怪效率。

### Phase 3：魔典與升級

- 三頁魔典白名單組合、12～15 升級卡、裝配 UI。
- 驗收：至少三種明顯不同 Build，可連續重玩；各卡條件與數值正確。

### Phase 4：連續探索與怪潮

- 完成從小屋至森林 Boss 的連續關卡與探索互動。
- 四普通怪、一精英、怪潮系統與 60 敵上限。
- 驗收：不透過固定競技場轉場完成 10 分鐘流程；能探索岔路和返回路線。

### Phase 5：Boss、超載與局外成長

- 三階段月蝕菇王、共鳴超載、返回工坊、研究/存檔、結果頁。
- 驗收：完成 10～12 分鐘一局並保留研究資源；死亡/勝利均可正常重開。

### Phase 6：正式美術與 Steam Demo 預備

- 正式角色四方向、地圖 Tileset、Props、VFX、音效、UI、操作教學、效能優化、Windows Build。
- 驗收：60 FPS 目標在指定硬體測試、無嚴重卡頓、完整操作教學、可在新電腦遊玩 Build。

### 絕不隱瞞的開發風險

- AI 生圖不等於可無縫重複的 Tileset；地形須修圖、驗證。
- 四方向角色 Sprite 與連續施法可能需要額外美術。
- 60 敵 + 華麗 Pixel VFX 的效能是目標，不是承諾。
- 魔法三頁系統的組合爆炸問題需透過白名單、預算與工具嚴格控管。
- 物理與魔法兩套攻擊若手感不清晰，需簡化鍵位及近戰價值。

## 17. Claude Code 工作規則
